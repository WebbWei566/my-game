# 《問道長生》規劃書

> 最後更新：2026-11-25｜目前進度：**M0～M5 主要功能完成，進入實機測試與內容擴充**｜版本 0.2.0

## 一、遊戲定位

| 項目 | 決定 |
|---|---|
| 類型 | 修仙放置＋文字奇遇＋輕度 Roguelite 秘境 |
| 平台 | 手機直式優先，桌機也能玩（PWA，可安裝到主畫面） |
| 單次遊玩 | 1～5 分鐘碎片時間，支援離線收益 |
| 美術風格 | 水墨、留白、宣紙色調、書法字體（Ma Shan Zheng） |
| 世界觀 | **原創**：宗門、地名、人物自行設計，不使用現有小說設定 |

## 二、核心循環

```
打坐修煉（累積修為）→ 境界突破（大境界需渡劫）→ 飛升 → 轉世（永久加成）
      ↑                          ↓
丹房：採藥／靈田／煉丹 ← 秘境：妖丹、靈草 → 藏經閣兌換功法
```

## 五、數值設計（`src/core/formulas.ts`）

| 項目 | 公式／數值 |
|---|---|
| 突破所需修為 | `100 × 1.55^階` |
| 每秒修為 | `1.32^階 × 靈根 × 功法 × 增益 × 轉世` |
| 每階所需時間（速度 ×1） | 約 `100 × 1.174^階` 秒：煉氣約 2 分鐘、結丹約 6～10 分鐘、化神約 20～35 分鐘、渡劫期每階約 5～8 小時 |
| 一周目總時長（速度 ×1） | 約 43 小時線上時間；實際會因功法、丹藥、離線收益而縮短 |
| 戰鬥成長 | 玩家與妖獸屬性皆為 `1.2^等級` |
| 秘境難度（模擬 400 次） | 剛解鎖時通關率約 20～55%，高一階約 55～95%，高兩階約 85～100% |

## 六、技術決策

| 項目 | 選擇 | 理由／備註 |
|---|---|---|
| 框架 | **Vue 3 + Pinia** | 遊戲以 UI 和狀態為主，Vue 響應式最省力 |
| 語言 | TypeScript | 數值和存檔結構多，型別能避免 bug |
| 建置 | Vite | 打包後約 60 KB（gzip） |
| PWA | vite-plugin-pwa（Workbox） | prompt 模式更新；Google Fonts 走 CacheFirst |
| 存檔 | idb-keyval（IndexedDB） | 失敗時退回 localStorage |
| 音效 | WebAudio 合成 | 不需音檔，離線可用 |
| 大數字 | **不使用** break_infinity.js | JS 原生數字可到約 1e308，36 階 + 轉世仍夠用 |
| 測試 | Vitest + happy-dom + fake-indexeddb + @vue/test-utils | `npm test`，含邏輯測試與 UI 冒煙測試（共 49 個） |
| 部署 | **GitHub Pages**（GitHub Actions） | `BASE_PATH=/<repo>/` 由 CI 傳入 |

### 程式結構

| 路徑 | 說明 |
|---|---|
| `src/data/` | 境界、靈根、物品、功法、丹方、奇遇、秘境、成就（**加內容只改這裡**） |
| `src/core/formulas.ts` | 數值公式與 `BALANCE` 參數 |
| `src/core/player.ts` | 存檔結構 `PlayerState`；新增欄位在 `defaultPlayer()` 補預設值即可 |
| `src/core/save.ts` | 存檔讀寫、版本遷移 `migrate()`、存檔碼 |
| `src/core/battle.ts` | 回合戰鬥（純函式） |
| `src/core/dungeonMap.ts` | 秘境地圖產生器 |
| `src/core/sfx.ts` | 音效 |
| `src/stores/game.ts` | 遊戲狀態、修煉、突破、物品、奇遇、存檔 |
| `src/stores/alchemy.ts`、`dungeon.ts`、`daily.ts` | 丹房／靈田、秘境戰鬥、每日的實作（由 game store 轉呼叫） |
| `src/views/` | 修煉、功法、丹房、秘境、行囊 |
| `src/components/` | 渡劫、火候、靈田、戰鬥、地圖、奇遇、設定、成就、開發者面板等 |
| `tests/` | `game.test.ts`（邏輯）、`dungeon.test.ts`（秘境）、`ui.test.ts`（UI 冒煙） |

### 開發原則
- **資料驅動**：內容放在 `src/data/`，測試會自動檢查 id 是否存在、是否重複
- **公式集中**：調整數值只改 `BALANCE`
- **存檔相容**：只新增欄位時補預設值；改名或改型別時才升版本並在 `migrate()` 加步驟
